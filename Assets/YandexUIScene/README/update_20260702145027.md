# 📝 更新记录: Yandex WebSocket 重连与排行榜系统集成 (2026-07-02 14:50:27)

本次更新的核心目标是：**优化 WebSocket 连线的稳定度及重连即时度**、**引入实时与结算排行榜组件及其精美瀑布动画**、**提供安全防护以及游戏数值的实时回显**。

---

## 1. 核心更新项汇总

### ⚡ 1. WebSocket 高阶断线感知与秒级重连 (`YandexWebSocketClient.cs`)
* **5.5 秒强行超时判定**：将心跳检测频率由 5s 提高至 **2s 检查一次**。通过记录每次接收消息的系统非缩放时间戳 `lastReceivedMessageTime`，若闲置超过 **5.5s** 未接收任何反馈（约连续丢 2 个包），自动执行强行断开并重建 Socket，将公网异常丢包感知从 30 秒级压缩至 **6 秒内**。
* **瞬间立刻重连**：当检测到初始连接断开的一瞬间，系统会**绕过 3 秒重连冷却**，瞬间调用 `Connect()` 发起首次重新连接；若首次连接失败，系统则自动切回 3 秒保护冷却时间轮询，以防止密集网络请求导致 CPU 或服务器过载。
* **重连 UI 闪烁保护**：在重连轮询重试期间，如果 UI 状态已为 `ErrorReconnecting`，则不再重置 WSSCanvas 面板，彻底解决网络错误时 Canvas 频繁闪退/闪烁的问题。
* **淡出打断安全机制**：在收到错误通知时执行 `StopTransition()`，不仅停掉成功时的淡出协程，还会调用 `canvasGroup.DOKill()` 打断任何正在进行的透明度过渡，保持面板完全显示，防止在闪断时错误面板意外隐去。

### 🖼️ 2. 二维码安全扫描与离线机制 (`YandexQRCodeGenerator.cs`)
* **智能隐藏防错扫**：当系统处于连接错误或首次连接状态时，由 WebSocketClient 自动下发隐藏指令，通过 CanvasGroup 的 alpha 平滑淡出（0.5s），并在淡出完毕后停用物体，避免玩家扫描已失效的连接口。连接恢复正常后，自动淡入恢复显示。
* **离线模式自动注销**：在 OFFLINE 离线模式下，直接停用二维码组件并隐藏其 RawImage，彻底屏蔽后台所有的生成与刷新协程，避免无效的 CPU 开销。

### 📊 3. 实时排行榜轮询组件 (`YandexLeaderboardManager.cs` - 新建)
* **2 秒高频轮询**：处于在线模式时，每隔 2 秒自动向外网 `https://yandexa.bbtech.cc/api/leaderboard` 发送 GET 请求并解析 JSON。
* **连接建立期静默**：游戏初次启动与连接服务器期间，排行榜完全保持清空与隐藏状态，不发起任何 HTTP 网络请求。仅在 `WSSCanvas` 关闭的瞬间触发拉取与刷新（包括场景重启和断网重连后）。
* **连接断开自动清空与限流**：当网络断开、WSSCanvas 弹出重连面板时，排行榜**自动清空现有数据并渐隐隐藏**，且**停止向外网发送任何 HTTP 请求**以节约带宽与 CPU。
* **网络恢复并关闭 Canvas 后呈现**：只有在网络重新连接成功、且 WSSCanvas 完全关闭（`IsCanvasClosed` 变为 true）后，排行榜才会重新启动轮询并以级联动画呈现。
* **瀑布级联排序动画**：对比本地缓存，**仅对排名/成绩发生变化的数据行**触发动画。多行刷新时，每一行自上而下顺次延迟 `0.08` 秒开始淡出（0.15s）、更新、淡入（0.25s），展现极具高级感 and 节奏感的动态滚屏排序视效。

### 🏆 4. 结算界面排行榜 (`YandexGameOverLeaderboard.cs` - 新建)
* **单次派发更新**：监听并接收从 WebSocket 下发的 `"type":"game_result"` 结算事件，收到消息后仅解析更新一次。
* **本局成绩醒目黄显**：自动解析返回数据中的 `currentPlayer`。如果列表中的某行数据与玩家本局的排名/姓名/分数匹配，该行的名次、名字、得分文本将被自动渲染为高亮黄色（颜色码：`#E1FA00`），便于玩家一眼看清自己的打榜成就。

### 🎮 5. 实时游戏分数显示 (`GameFlowController.cs`)
* **分数文本实时同步**：新增 `gameScoreTMP` 引用项，在 `Update` 核心循环中执行 `gameScoreTMP.text = gameScore.ToString();`。无论是 Debug 模式下通过 PageUp/PageDown 快捷修改分数，还是核心玩法中其他角色逻辑变更了分数，都将以 0 延迟渲染到 UI 上。

### 🔄 6. 场景开发极简化与动态自适应 (`SceneReLoad.cs` & `GameModeSelector.cs`)
* **统一加载活动场景**：重构了 `SceneReLoad.cs` 和 `GameModeSelector.cs` 的重载机制，使用 `SceneManager.GetActiveScene().name` 代替写死的双场景加载。
* **物理双场景合并**：现在无需维护 `GameONLINE` 和 `GameOFFLINE` 两个场景，全部统一合并到单个场景开发中。
* **组件级自适应开关**：重载时各组件自动获取 PlayerPrefs 中的 GameMode 并执行开关（如离线模式下 WebSocket 主动断开、二维码自动停用淡出、排行榜自动清空），极大地提升了美术及 UI 资产的开发维护效率。
