# 📝 更新记录: 排行榜与二维码场景重载状态同步及重复刷新修复 (2026-07-02 18:48:32)

本次更新解决了游戏重启/重载场景（Scene Reload）后二维码无法显示、初始渐隐状态残留，以及启动时排行榜出现重复刷新（触发两次 Connection Connected）的重大逻辑漏洞。

---

## 1. 核心修复与优化项

### 🚫 1. 彻底取消分散的状态控制与集中式生命周期接管
* **单一控制源**：移除了 `YandexWebSocketClient.cs` 内部对二维码 `SetQRImageActive` 的直接操作，并移除了 `YandexQRCodeGenerator.cs` 自带的对模式显隐的处理。
* **统一事件控制**：目前只有当 `YandexLeaderboardManager.cs` 中的连接观测器真正输出 `[Leaderboard] Network state detected as Connected. Fetching immediately!` 状态时，才将 `Ranking` 父物体和 `RawImage-qrcore` 二维码组件同步设为 `SetActive(true)` 并开始展示。

### ⚡ 2. 场景重载/初始化状态下直接关闭 (无渐隐) 与数据彻底清空
* **直截了当的初始态**：在 `Awake` 及场景重新加载 `OnSceneLoaded` 时，`RawImage-qrcore` 会立刻执行 `SetActive(false)` 直接隐藏，取消任何 DOTween 渐隐效果，防止闪烁或首帧的幽灵显示。
* **TMP 彻底清空**：当排行榜执行 `HideAndClearImmediately` 时，不再仅局限于原先匹配的 Row 成员，而是使用 `GetComponentsInChildren<TextMeshProUGUI>(true)` 深度遍历 10 个子排位行的每一个文本框，强制置为 `""` 空字串，确保在未连线成功前不展示任何历史或默认文本。

### 🛠️ 3. 修复网络状态误判导致的“双倍 Connected / 重复拉取” Bug
* **原因剖析**：先前使用 `IsCanvasClosed` 作为检测是否已建立连接的代理条件。然而在游戏刚启动或场景刚重载时，WebSocket 物理连接尚未创建或正在连接中，此时 Canvas 尚未激活（状态默认为 `Hidden`），从而被排行榜误判为“已成功连接”，导致在启动时先触发一次 “Connected”，在网络握手真正成功 Canvas 隐藏后又再次触发一次 “Connected”（即总共触发了两次网络请求，产生了多余的排行榜拉取与 QR 二维码生成逻辑）。
* **引入物理连接校验**：在 `YandexWebSocketClient.cs` 中新增暴露了物理连接属性：
  ```csharp
  public bool IsWebSocketOpen => webSocket != null && webSocket.IsOpen;
  ```
  在 `YandexLeaderboardManager.cs` 中，将已连接的判定条件升级为：
  ```csharp
  bool isConnected = YandexWebSocketClient.Instance != null 
      && YandexWebSocketClient.Instance.IsWebSocketOpen 
      && YandexWebSocketClient.Instance.IsCanvasClosed;
  ```
  只有物理网络通道已开启且遮罩面板已成功隐去，才被认为是有效的连接态。完美消除了初始化阶段的伪 Connected 信号，实现了场景重载后有且仅有一次的顺畅刷新。
